# HFOC OS 1.0.0

Первый продуктовый выпуск HFOC OS: устанавливаемая appliance-система с
веб-панелью, SSH-администрированием, нативной оболочкой и сохраняемым
рабочим каталогом владельца.

## Поддержанная конфигурация

- x86-64, один процессор, legacy 8259 PIC, PIT, PS/2-клавиатура;
- загрузка через Limine (BIOS/UEFI-носитель по штатному процессу);
- сеть через поддерживаемый Ethernet-драйвер, DHCP;
- management-interface, публичный SSH только по ключу владельца;
- консоль 1024x768, native Fixed 8x16 glyphs, чёрный фон;
- установка whole-disk и state-preserving update по объявленному носителю
  с явной декларацией target/management/layout/network.

## Установка и обновление

- Установщик проверяет target, management, layout, SSH-ключ и сеть до первой
  записи; несовпадение identity — отказ без записи.
- Полная декларация носителя принимается до 1024 байт; более длинная
  отклоняется по имени (`TOKEN_TOO_LARGE`) до первой записи.
- Обновление с сохранением состояния: установленное состояние не
  пересоздаётся; в QEMU отдельно проверены аккаунт владельца, SSH host key,
  авторизованный client key и файлы `/home/owner` (те же байты после reboot
  и после повторного обновления). Сертификаты и сетевые настройки входят в
  сохраняемые state stores, но отдельным release-тестом не переутверждаются.
- Восстановление — по действующему recovery-процессу; support/recovery
  токены не получают интерактивную оболочку.

## Панель и SSH

- Веб-панель: локальный вход, управление сетью/маршрутами/сертификатами,
  диагностика; сессия в HttpOnly-cookie.
- Панель остаётся доступной во время длительной проверки пароля: KDF
  выполняется кооперативно, без блокировки сетевого цикла; размер среза
  целится в 40 мс работы и зажат между доказанным минимумом и максимумом.
  Пока активное соединение владеет ожидающей проверкой, цикл выполняет
  ограниченный burst (100 мс или четыре среза) и не паркуется в `cpu_hlt()`;
  сеть, консоль, журнал и watchdog работают между burst'ами.
- Завершённая запись `[PANEL-AUTH]` разделяет измеренное время KDF
  (`kdf_us`) и ожидание между срезами (`wait_us`), сохраняя число срезов,
  худший разрыв и итоговые раунды; секреты в запись не попадают.
- SSH: только publickey для enrolled owner identity, pin host key;
  интерактивный PTY-shell, history/editing, resize, Ctrl-C/Ctrl-D,
  корректный exit/disconnect; повторный второй сеанс после закрытия первого
  проверен, одновременные владельческие сеансы не заявлены.
- Все видимые поля панели несут подпись только на выбранном языке
  (`ru`/`en`); форма удаления маршрута содержит только имя.
- Добавление и удаление маршрута — две визуально разные формы: отдельные
  заголовки, подпись поля удаления и отдельные кнопки; третья форма остаётся
  двухфазным подтверждением.
- Локальная консоль не рисует правый блок `UPTIME` и не вставляет адрес
  управления в строку логина или пароля; уведомление выходит отдельной
  строкой на границе приглашения.
- Старые diagnostic exec-команды, collector и CRC STREAM сохранены.

## Сеть и веб-маршрут

- Настроенный HTTPS-маршрут к объявленному backend проверяется с проверкой
  сертификата и совпадением probe id в журнале backend; маршрут переживает
  перезагрузку в пределах сохранённого состояния.
- Отказ backend освобождает relay-слот: lwIP-ошибка `ERR_ABRT` после
  исчерпания SYN-retries больше не принимается за собственный abort.
  Ограниченный отказ первого клиента и приём следующего после восстановления
  backend доказаны host-регрессией; это software proof, физическая проба
  backend-down на Toshiba остаётся отдельным открытым критерием.
- Приём RTL8168 останавливался на `RxOverflow|RxFIFOOver`: poll-драйвер
  теперь подтверждает наблюдённое слово `IntrStatus` на каждом проходе
  (write-one-to-clear), удерживая пару `RxFIFOOver|RxOverflow` до
  доказанного свободного RX-дескриптора. `[NET-RX]` публикует `rx_ovf` и
  `rx_ovf_ack`, чтобы следующий физический снимок показал остановку и её
  снятие. Это software proof: восстановление приёма на Toshiba остаётся
  отдельным открытым аппаратным критерием.
- Импорт сертификата для имени при непроверенных часах отвечает
  `{"refused":"BAD_CLOCK"}` вместо общего `REFUSED`; остальные отказы
  сохраняют прежний ответ.
- Установленная запись принимает явный unicast-сервер времени
  `hfoc.sntp=<IPv4>`; носитель запечатывает его из
  `HFOC_INSTALL_MEDIA_SNTP=`. Без директивы источник прежний — активный
  шлюз. Ответ принимается только от выбранного адреса, на активный локальный
  адрес и с совпадающими портами/`originate`; некорректный или не-unicast
  адрес публикуется как `sntp=INVALID` и `clock=UNSYNCHRONIZED`, сеть не
  отказывает.
- `[NET-RX]` публикует read-only снимок регистров и RX-дескрипторов RTL8168
  в `network`/`journal`/`diag`; снимок сам приём не изменяет.

## Оболочка и файлы

- Нативные ELF64-программы в `/bin`: `sh`, `ls`, `cat`, `cp`, `mv`, `rm`,
  `mkdir`, `echo`, `pwd`, `grep`, `wc`, `sleep`, `true`, `false`, `hfoc`.
- `sh`: quoting, переменные, `PATH`, `$?`, `;` `&&` `||`, redirections
  `<` `>` `>>` `2>` `2>&1`, pipelines, `cd`/`export`/`unset`/`exit`,
  условия/циклы/функции, позиционные параметры, subshell и command
  substitution в документированном объёме; `cmd &`, `jobs`, `fg`, `bg`,
  `wait` с ограниченной таблицей jobs. Точная матрица —
  `docs/hfoc-sh-syntax-632.md`.
- VFS: каталоги/файлы/cwd, чтение/запись/rename/unlink, дескрипторы и file
  descriptions, понятные ошибки и лимиты; `/bin` и `/etc` из initramfs,
  `/tmp` и `/run` в RAM. Unix permissions/uid/gid, symlink и special files
  не реализованы и не заявляются.
- `/home/owner` — сохраняемый workspace на HFOCFS (COW-commit, две
  superblock-генерации с fallback на предыдущую, checksummed metadata);
  файлы переживают reboot и state-preserving update (доказано в QEMU).

### Исправления shell по физической приёмке

- ITEM-656: диагностика нативного userland пишется в descriptor 2;
  `2>file` перехватывает сообщение, `2>&1` остаётся слитым, а обычный
  вывод программ по-прежнему идёт в stdout.
- ITEM-658: интерактивный редактор сохраняет UTF-8, историю и черновик;
  стрелки, Backspace и Delete работают по code point, Down возвращает
  недописанную строку, а PTY принимает штатное RFC 4254 mode framing.
- ITEM-659: отсутствующая команда выполняет собственные redirections и
  возвращает статус 127; `nosuchcommand 2>file` создаёт файл, оставляет
  `>file` пустым и не пишет диагностику в терминал.

## Ограничения

- Это не Linux: Linux binary ABI, glibc/Bash/BusyBox и полная POSIX-
  сертификация не заявлены. Матрица поддержанного `sh` — в документации.
- Веб-маршрут настраивается на объявленный backend; произвольный TCP-
  проброс портов — отдельный сценарий.
- Файловый namespace — не host Unix root: host-диски не монтируются,
  raw block/mem/kernel/panic-каналы не экспортируются.
- Восемь fixed state stores защищённого состояния не являются свободным
  местом rootfs.
- Холодный первый вход в панель сразу после загрузки может занимать около
  33 с (измерено 33,399 с) при установившемся входе около 25 с. Это
  известное ограничение cold-start, а не дефект KDF, entropy или lockout.
- Физическая приёмка конкретной Toshiba-конфигурации фиксируется в отчёте;
  QEMU-прогон не равен hardware proof.
