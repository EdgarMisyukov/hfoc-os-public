# Справочник по нативной оболочке

[Главная](../README.ru.md) · [Первый запуск и управление](operate.ru.md) · [English](shell.md) · Русский

Справочник описывает нативную оболочку `/bin/sh` из HFOC OS 1.0.0. Она запускает программы HFOC в формате ELF64 и реализует описанное ниже подмножество командного языка. Возможности выпуска перечислены в [примечаниях к версии 1.0.0](release-1.0.0.ru.md).

## Подключение и командная строка

Зарегистрируйте открытый ключ владельца и проверьте ключ SSH-сервера по инструкции [Первый запуск и управление](operate.ru.md). Выполните команду на клиенте SSH. Подставьте адрес управления вместо `HFOC_ADDRESS` и укажите пути к закрытому ключу и к файлу с проверенным ключом сервера.

```sh
ssh -tt -i ~/.ssh/hfoc_owner -o IdentitiesOnly=yes \
  -o UserKnownHostsFile="$HOME/.ssh/hfoc_known_hosts" \
  -o StrictHostKeyChecking=yes hfoc@HFOC_ADDRESS
```

- Вводите команды в строке с приглашением `hfoc$`. Приглашение `>` запрашивает следующую строку незавершённой составной команды. Ctrl+C в строке ввода отменяет всю текущую команду вместе с предыдущими строками продолжения и устанавливает код 130. Ctrl+D на пустой строке или команда `exit` завершает работу оболочки.
- Аргументы и имена файлов можно вводить в UTF-8. Стрелки влево и вправо перемещают курсор на одну кодовую точку Unicode. Backspace удаляет предыдущую кодовую точку, в том числе если клиент передаёт для Backspace байт DEL. Отдельная последовательность клавиши Delete не выполняет удаление справа от курсора.
- Стрелки вверх и вниз позволяют выбрать до восьми последних введённых строк, суммарно до 4096 байт. Переход вниз после самой новой записи возвращает черновик и положение курсора. История доступна в пределах сеанса.
- Длинная строка прокручивается горизонтально в пределах одного ряда терминала. После вывода без перевода строки редактор выводит приглашение на новом ряду. SSH принимает изменения размера окна, а редактор использует ширину на момент запуска оболочки. Переподключитесь, чтобы редактор использовал новую ширину.

Храните постоянные файлы в `/home/owner`. Каталоги `/tmp` и `/run` находятся в памяти. Каталоги `/bin` и `/etc` читаются из системного образа. В сеансе SSH переменная `HOME` имеет значение `/tmp`. Чтобы перейти в постоянный рабочий каталог, выполните `cd /home/owner`. Текущий каталог показывает команда `pwd`.

## Команды, слова и коды завершения

В `/bin` доступны нативные программы `sh`, `ls`, `cat`, `cp`, `mv`, `rm`, `mkdir`, `echo`, `pwd`, `grep`, `wc`, `sleep`, `true`, `false` и `hfoc`. У каждой программы свой набор параметров. Имя команды со знаком `/` используется как путь. Для остальных внешних команд оболочка перебирает непустые элементы `PATH`, разделённые двоеточиями. Если переменная `PATH` не задана или пуста, поиск выполняется в `/bin`.

| Синтаксис | Действие |
| --- | --- |
| `'text'` | Слово без подстановок. |
| `"text"` | Одно слово с подстановками через `$`. Внутри двойных кавычек обратная косая черта экранирует `"`, `\` и `$`. |
| `\` вне кавычек | Экранирует следующий байт. |
| `# comment` | Начинает комментарий на границе слова. |
| `$NAME`, `${NAME}` | Подставляет значение переменной. Для незаданной переменной подставляется пустая строка. |
| `$?` | Подставляет код завершения последней команды или списка. Ноль означает успех. |
| `;`, перевод строки | Разделяют команды и списки. |
| `&&`, `\|\|` | Запускают следующий конвейер при нулевом или ненулевом предыдущем коде соответственно. |
| `\|` | Соединяет stdout одного звена конвейера со stdin следующего. В звеньях используйте внешние программы. |

Обычно результат подстановки остаётся частью того же слова. Исключение для отдельного слова `$@` или `"$@"` описано ниже. Оболочка не разбивает результаты подстановок на слова и не раскрывает шаблоны имён файлов. Пути с пробелами заключайте в кавычки. Имена файлов указывайте явно. Без управления заданиями завершённый конвейер возвращает код последнего звена. При управлении заданиями возвращается код процесса конвейера, завершение которого оболочка обработала последним.

Самостоятельное присваивание `NAME=value` сохраняет значение в оболочке и возвращает код 0, даже если для значения использовалась подстановка команды. Форма `NAME=value command` задаёт значение для одной простой команды, после которой восстанавливается предыдущее значение. Используйте `export NAME=value`, чтобы явно задать значение для дочерних процессов. В этом выпуске оболочка передаёт дочерним процессам и значения самостоятельных присваиваний. Подстановки в аргументах команды выполняются раньше присваиваний перед командой.

```sh
MESSAGE='hello world'
echo "${MESSAGE}"
MESSAGE=temporary /bin/sh -c 'echo "$MESSAGE"'
echo "$MESSAGE"
false; echo "status=$?"
true && echo success
false || echo fallback
```

## Перенаправления и файлы

| Синтаксис | Действие |
| --- | --- |
| `< file` | Читает stdin из файла. |
| `> file` | Создаёт или очищает файл для stdout. |
| `>> file` | Дописывает stdout нативной программы в конец файла и создаёт файл при необходимости. |
| `2> file` | Создаёт или очищает файл для stderr. |
| `2>&1` | Направляет stderr туда, куда в этот момент направлен stdout. |

Порядок перенаправлений важен. Конструкция `> file 2>&1` направляет оба потока в файл. Нативные программы пишут диагностические сообщения в stderr, а обычный вывод в stdout. Если имя команды отсутствует в пути поиска, оболочка применяет перенаправления, пишет сообщение `command not found` в stderr и возвращает код 127. Файл stdout создаётся пустым, если stderr не перенаправлен в тот же файл.

Создайте новый временный каталог для примеров. Переходите к примерам с файлами после успешного выполнения команды. Если каталог уже существует, выберите свободный путь и подставьте его в обе команды.

```sh
mkdir /tmp/hfoc-shell-demo && cd /tmp/hfoc-shell-demo
```

```sh
echo 'hello HFOC' > 'sample мир.txt'
echo 'second line' >> 'sample мир.txt'
cat < 'sample мир.txt' | wc -l
hfoc_no_such_command > stdout.txt 2> stderr.txt
echo "status=$?"
cat stderr.txt
hfoc_no_such_command > combined.txt 2>&1
cat combined.txt
```

Конвейер насчитает две строки. Первая отсутствующая команда вернёт 127, оставит пустой `stdout.txt` и запишет диагностику в `stderr.txt`. Вторая запишет диагностику в `combined.txt`.

## Сценарии и позиционные параметры

Для запуска файла используйте `/bin/sh path/to/script arg ...`. Для запуска строки команд используйте `/bin/sh -c 'commands' label arg ...`. При запуске из файла `$0` содержит путь сценария. С параметром `-c` необязательная метка `label` задаёт значение `$0`, а следующие аргументы становятся позиционными параметрами.

- Для обращения к отдельным аргументам используйте `$1`–`$9`. Переменная `$#` содержит количество позиционных параметров.
- Слово, состоящее ровно из `$@` или `"$@"`, разворачивается в одно слово на каждый параметр с сохранением пустых аргументов. Если параметров нет, подстановка не создаёт слов. Внутри слова подстановка `$@` соединяет параметры пробелами, как и `$*`.
- Команда `shift [count]` убирает позиционные аргументы с начала списка. По умолчанию убирается один аргумент.

Запишите и выполните сценарий во временном каталоге, созданном выше. Он выведет `first argument` и `second` на отдельных строках.

```sh
echo 'for item; do echo "$item"; done' > show-args.sh
/bin/sh ./show-args.sh 'first argument' second
/bin/sh -c 'echo "$0: $# arguments"; echo "$1"' demo 'first argument' second
```

## Условия, циклы и функции

| Форма | Действие |
| --- | --- |
| `if list; then list; elif list; then list; else list; fi` | Выполняет ветвь, условие которой вернуло 0. Части `elif` и `else` необязательны. |
| `for name in words; do list; done` | Перебирает слова после подстановок. |
| `for name; do list; done` | Перебирает позиционные параметры. |
| `while list; do list; done` | Повторяет тело цикла, пока условие возвращает 0. |
| `until list; do list; done` | Повторяет тело цикла, пока условие не вернёт 0. |
| `name() { list; }`, `function name { list; }` | Определяет функцию. Её аргументы временно заменяют позиционные параметры. |
| `{ list; }` | Группирует команды в текущей оболочке. |
| `( list )` | Выполняет список с сохранением состояния оболочки. Изменения переменных, текущего каталога и позиционных параметров действуют внутри группы. Изменения файлов сохраняются. |

В интерактивном режиме определение функции действует в пределах одного буфера ввода. Определите и вызовите её на одной строке либо поместите определение и вызов в сценарий. `return [status]` завершает функцию. `break [1]` выходит из ближайшего цикла, а `continue [1]` переходит к его следующей итерации.

Используйте `$(list)`, чтобы получить stdout дочерней оболочки `/bin/sh`. Оболочка удаляет переводы строк в конце вывода и сохраняет результат в составе одного слова. Поток stderr остаётся отдельным. Выражение в парных обратных кавычках в этой версии не раскрывается.

```sh
greet() { echo "hello $1"; }; greet owner
if [ -d /home/owner ]; then echo workspace; else echo no-workspace; fi
for word in alpha 'beta gamma'; do echo "$word"; done
while true; do echo once; break; done
VALUE=before
( VALUE=inside; cd /tmp; pwd; echo "$VALUE" )
echo "$VALUE"
{ VALUE=after; echo "$VALUE"; }
echo "captured=$(echo native)"
/bin/sh -c 'trap "echo leaving" EXIT; echo running'
```

## Встроенные команды

| Команда | Действие |
| --- | --- |
| `cd [directory]` | Меняет текущий каталог. Без аргумента использует `HOME`, а если эта переменная не задана или пуста, переходит в `/`. |
| `export NAME=value`, `unset NAME` | Задают значение переменной окружения или удаляют переменную. |
| `exit [status]` | Завершает работу оболочки. Если аргумент опущен, используется предыдущий код завершения. |
| `test expression`, `[ expression ]` | Возвращают 0 для истинного выражения, 1 для ложного или 2 для недопустимого. Символы `[` и `]` должны быть отдельными словами. |
| `shift [count]`, `return [status]` | Сдвигают позиционные параметры или завершают функцию. Без аргумента `return` использует предыдущий код завершения. |
| `break [1]`, `continue [1]` | Управляют ближайшим циклом. |
| `trap 'command' EXIT`, `trap - EXIT` | Задают или отменяют одну команду, которая выполняется при штатном завершении оболочки. `EXIT` — единственное поддерживаемое событие. |
| `jobs`, `fg [%n]`, `bg [%n]`, `wait [%n]` | Показывают задания текущей оболочки или управляют ими. |

В `test` и `[` используйте одну строку (истина, если она непустая), `-n string`, `-z string` или `! string`. Проверки файлов поддерживают формы `-e path`, `-f path`, `-d path`, `-r path` и `-w path`. Опция `-r` проверяет, доступен ли поиск по указанному пути. Опция `-w` дополнительно проверяет признак «только для чтения». Для сравнения строк используйте `=` и `!=`. Для сравнения целых чисел используйте `-eq`, `-ne`, `-lt`, `-le`, `-gt` и `-ge`. Отдельные проверки можно объединять операторами оболочки `&&` и `||`.

## Задания и сигналы терминала

Завершите простую команду, конвейер или цепочку с `&&` и `||` знаком `&`, чтобы запустить её в фоновой дочерней оболочке с отдельной группой процессов. После составной команды напрямую ставить `&` нельзя. Дочерняя оболочка наследует текущий каталог, стандартные потоки и окружение. Определения функций родительской оболочки действуют только в её буфере ввода. Фоновая группа не может читать ввод из терминала владельца.

- `jobs` показывает задания в формате `[n] Running|Stopped|Done command`.
- `fg [%n]` переводит задание на передний план, возобновляет его, если оно остановлено, ждёт и возвращает код завершения задания.
- `bg [%n]` возобновляет остановленное задание в фоне. Без номера `bg` и `fg` выбирают выполняющееся или остановленное задание с наибольшим номером.
- `wait [%n]` ждёт указанное задание или все незавершённые задания и возвращает код, полученный последним. Перед ожиданием остановленного задания возобновите его, если хотите дождаться завершения.

Запустите короткое фоновое задание и дождитесь его завершения.

```sh
sleep 5 &
jobs
wait
echo "status=$?"
```

Для проверки управления заданиями введите `sleep 30` и нажмите Ctrl+Z, пока команда выполняется. Введите `jobs`, чтобы увидеть остановленное задание, `bg`, чтобы возобновить его, и `fg`, чтобы вернуть его на передний план. Нажмите Ctrl+C, чтобы прервать задание и вернуться к приглашению.

Пока терминал занят заданием на переднем плане, Ctrl+C посылает `SIGINT`, Ctrl+\ посылает `SIGQUIT`, а Ctrl+Z посылает `SIGTSTP` его группе процессов. Запросы сигналов SSH `INT`, `QUIT`, `TSTP`, `CONT`, `TERM` и `HUP` также направляются этой группе. Если задания на переднем плане нет, сигналы SSH `TERM` и `HUP` завершают сеанс. При закрытии сеанса SSH его задания получают `SIGHUP`. Для сигналов используются действия по умолчанию.

## Пределы и неподдерживаемый синтаксис

| Ресурс | Предел |
| --- | --- |
| Сценарий или строка для `-c` | Буфер 10 КиБ с учётом завершающего байта. |
| Разбор структуры | 1024 токена, 128 узлов синтаксического дерева, 512 элементов списков во всём дереве, 64 команды в списке, шесть уровней вложенности составных команд. |
| Ввод простой команды | Буфер 4096 байт с учётом завершающего байта. |
| Аргументы и перенаправления | 64 аргумента с учётом имени команды, восемь перенаправлений на команду, восемь присваиваний перед одной командой. |
| Конвейеры и условные цепочки | Восемь звеньев на конвейер, четыре конвейера в цепочке с `&&` и `\|\|`. |
| Переменные оболочки | 12 переменных с учётом унаследованных. Имя до 63 байт, значение до 255 байт. |
| Функции и подоболочки | 32 функции, шесть активных вызовов функций, две вложенные подоболочки в круглых скобках. |
| Циклы и подстановки | 32 слова в заголовке `for ... in`, 10 000 итераций `while` или `until`, до 4096 байт stdout на подстановку команды. |
| Позиционные параметры | Десять сохраняемых аргументов длиной до 255 байт каждый. Индексы отдельных параметров доступны от `$1` до `$9`. |
| Задания | Восемь заданий и восемь отслеживаемых процессов на задание. Буфер описания задания занимает 128 байт. |

Оболочка проверяет структуру ввода перед исполнением. Ошибка структуры составной команды в сценарии приводит к коду завершения 2. Ошибки отдельных команд и подстановок могут возникать при их выполнении. Подстановка с объёмом вывода сверх допустимого завершается ошибкой с диагностическим сообщением.

В подмножество языка не входят `case`, `select`, `time`, арифметические подстановки, `set -e`, массивы, подстановка процессов, here-документы, обработчики сигналов в оболочке и встроенная команда `kill`. Группы команд служат для выполнения списков. В каждом звене конвейера используйте внешнюю программу и применяйте перечисленные выше перенаправления.
