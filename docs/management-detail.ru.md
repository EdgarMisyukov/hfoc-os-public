# Управление и восстановление HFOC OS 1.0.0

[Первый запуск и управление](operate.ru.md) · [English](management-detail.md) · Русский

## Первый запуск и учётная запись администратора

1. Загрузитесь с установленного диска. Оставьте локальную консоль доступной
   на время настройки сети. Команда `network` показывает адрес управления и
   состояние часов.
2. Если установщик оставил учётную запись ненастроенной, выполните
   `credentials` в локальной консоли. По запросу введите имя администратора и
   дважды новый пароль. Имя чувствительно к регистру и содержит от 1 до 32
   букв латиницы, цифр, точек, символов подчёркивания или дефисов. Используйте
   уникальный пароль из 12–128 печатных символов ASCII. Убедитесь, что
   настройка завершилась успешно. Для локального входа по паролю выполните
   `login`.
3. Из сети управления откройте `https://<management-address>/panel`. Перед
   вводом пароля проверьте сертификат сервера. Для самоподписанного сертификата
   устройства сравните отпечаток SHA-256 в браузере со значением, полученным
   через доверенное прямое подключение по описанной ниже процедуре. Первый
   вход после загрузки может занять около 33 секунд. Дождитесь результата,
   прежде чем повторно отправлять форму.
4. Откройте раздел **Сеть**, подготовьте настройки DHCP или статического IPv4
   и подтвердите их токеном из панели. После перезагрузки выполните
   `network` в консоли, чтобы проверить активный адрес перед подключением.

Для смены учётной записи в панели откройте раздел **Учётная запись**,
укажите текущий пароль, новое имя и новый пароль, затем подтвердите изменение
одноразовым токеном. Изменение завершает сеанс, из которого отправлено
подтверждение, и все остальные сеансы панели. Войдите с новыми данными.

Для первого подключения с самоподписанным сертификатом соедините рабочую
станцию с устройством напрямую или используйте изолированный сегмент
управления под вашим контролем. Получите отпечаток по этому соединению,
прежде чем пользоваться другой сетью. Подставьте адрес из вывода `network`.

```sh
HFOC_ADDRESS=192.0.2.10
openssl s_client -connect "$HFOC_ADDRESS:443" -noservername </dev/null 2>/dev/null \
  | openssl x509 -noout -sha256 -fingerprint
```

## Время и HTTPS по имени

По умолчанию устройство запрашивает время у активного шлюза. Чтобы назначить
другой доступный сервер SNTP в локальном сегменте, укажите
`HFOC_INSTALL_MEDIA_SNTP=192.0.2.20` при сборке носителя с декларацией
установки или обновления. В строке загрузки установленной системы появится
`hfoc.sntp=192.0.2.20`. Вместо примера подставьте IPv4-адрес вашего сервера,
предназначенный для одноадресной передачи. См. [руководство по загрузке и
установке](install.ru.md).

После загрузки выполните `network` и дождитесь `clock=READY` перед импортом
сертификата для имени. Если панель отвечает `BAD_CLOCK`, проверьте выбранный
адрес SNTP и доступность UDP-порта 123 с устройства. Повторите импорт, когда
часы синхронизируются.

1. Настройте DNS для нужного имени. Подготовьте действующий сертификат с
   этим точным именем в SAN и соответствующий закрытый ключ ECDSA P-256.
2. В разделе **Сертификаты** (`/panel/certificates`) укажите имя, сертификат
   в формате PEM и соответствующий ключ PEM. Подготовьте импорт, проверьте
   отложенную операцию и подтвердите её показанным одноразовым токеном.
3. Перезагрузите систему, чтобы она загрузила сохранённый сертификат.
   Подключайтесь по имени DNS, чтобы клиент передал нужное имя сервера (SNI).
   Проверьте цепочку и имя с помощью хранилища доверия клиента или сертификата
   соответствующего центра сертификации.

На странице **Безопасность** (`/panel/security`) находится форма импорта
сертификата самого устройства с отдельным необязательным полем для цепочки.
Страница **Сертификаты** управляет сертификатами для отдельных имён.

## Ключ SSH-клиента и ключ устройства

Для входа по SSH используется имя `hfoc` и зарегистрированный открытый ключ
владельца ECDSA P-256. Если подходящего ключа ещё нет, создайте его на своей
рабочей станции. Закрытый ключ храните на этой станции.

```sh
install -d -m 700 "$HOME/.ssh"
ssh-keygen -t ecdsa -b 256 -f "$HOME/.ssh/hfoc_owner"
ssh-keygen -lf "$HOME/.ssh/hfoc_owner.pub"
```

Носитель обновления с декларацией может установить этот ключ. В
`HFOC_INSTALL_MEDIA_SSH_KEY` укажите файл `.pub`, а в
`HFOC_INSTALL_MEDIA_SSH_KEY_CONFIRM` — его отпечаток `SHA256:…`. Для
регистрации в локальной консоли извлеките открытую точку из ключа OpenSSH
в виде строки base64 из 88 символов. Выполните на рабочей станции с Python 3
ту же команду, что в английской версии.

```sh
python3 - "$HOME/.ssh/hfoc_owner.pub" <<'PY'
import base64
import struct
import sys
from pathlib import Path

key_type, encoded, *_ = Path(sys.argv[1]).read_text().split()
if key_type != "ecdsa-sha2-nistp256":
    raise SystemExit("Expected an ECDSA P-256 public key")
blob = base64.b64decode(encoded, validate=True)
fields = []
for _ in range(3):
    size, = struct.unpack(">I", blob[:4])
    fields.append(blob[4:4 + size])
    blob = blob[4 + size:]
algorithm, curve, point = fields
if (algorithm != b"ecdsa-sha2-nistp256" or curve != b"nistp256" or blob
        or len(point) != 65 or point[0] != 4):
    raise SystemExit("Invalid ECDSA P-256 public key blob")
print(base64.b64encode(point).decode("ascii"))
PY
```

После `login` или `credentials` выполните в локальной консоли
`ssh-key add <88-character-base64-point>`. Сравните отпечаток
кандидата с выводом `ssh-keygen -lf` и выполните
`ssh-key confirm <SHA256:fingerprint>` с точным значением. Командой
`ssh-key show` проверьте отпечаток зарегистрированного клиента
(`authorized=`) и ключа устройства (`host=`). Для отзыва ключа клиента
выполните `ssh-key remove` после входа в локальной консоли.

Вместо адреса из примера подставьте адрес управления устройства. Получите
кандидат на ключ SSH-сервера и сравните его отпечаток со значением
`host=`, полученным в локальной консоли.

```sh
HFOC_ADDRESS=192.0.2.10
ssh-keyscan -t ecdsa "$HFOC_ADDRESS" > hfoc-host.candidate
ssh-keygen -lf hfoc-host.candidate
```

Сохраните привязку в отдельный файл только после совпадения отпечатков.
Выберите свой файл для каждого устройства и проверьте существующую привязку
перед заменой.

```sh
install -m 600 hfoc-host.candidate "$HOME/.ssh/hfoc_known_hosts"
ssh -t -i "$HOME/.ssh/hfoc_owner" -o IdentitiesOnly=yes \
  -o UserKnownHostsFile="$HOME/.ssh/hfoc_known_hosts" \
  -o StrictHostKeyChecking=yes "hfoc@$HFOC_ADDRESS"
```

Для диагностики без интерактивного терминала выполните ту же команду `ssh`
без `-t` и добавьте `'hfoc diag'` после адреса назначения. Если сеть
недоступна, выполните `diag save` в локальной консоли с подготовленным
диагностическим носителем. См. [руководство по первому запуску](operate.ru.md)
для работы с отчётом.

## Маршрутизация HTTPS

В разделе **Маршрутизация** (`/panel/routing`) подготовьте маршрут с точным
именем DNS, IPv4-адресом и портом объявленного бэкенда и настройкой TLS
для бэкенда. Подтвердите операцию и убедитесь, что запись появилась в таблице
действующих маршрутов. Для удаления выберите **Удалить**, укажите имя
маршрута и подтвердите операцию.

Фасад HTTPS завершает TLS-соединение от клиента и отправляет запрос HTTP
бэкенду при `tls=off`. Используйте этот режим в доверенной сети бэкенда.
Запрос к маршруту с `tls=on` получает отказ HTTP 503. Ограничьте сетевым
экраном и настройками бэкенда доступ до нужного трафика. Пути `/panel` и
`/api/` остаются точками входа управления.

Например, направьте `app.example.org` на устройство и импортируйте
сертификат для этого имени. Настройте маршрут к нужному бэкенду и проверьте
его с рабочей станции управления, у которой есть доверенный сертификат
центра сертификации. Подставьте своё имя, адрес, файл сертификата центра
и путь, который обслуживает ваш бэкенд.

```sh
curl --fail --cacert management-ca.pem \
  --resolve app.example.org:443:192.0.2.10 https://app.example.org/facade
```

Сверьте ответ с журналом бэкенда. Если настроен отдельный объявленный
перенаправитель TCP на порту 9443, проверьте эту точку входа по имени
бэкенда и порту 9443. В этом режиме сертификат предъявляет бэкенд, а
подключения разрешены только с явно перечисленных IPv4-адресов клиентов.

## Восстановление доступа

- **Забыт пароль администратора.** Последовательно введите в локальной
  консоли две команды. Любая другая команда между ними отменит ожидание
  подтверждения.

  ```text
  credentials reset
  credentials reset confirm
  ```

  Дождитесь `state=UNPROVISIONED`, задайте новую учётную запись командой
  `credentials` и заново зарегистрируйте ключ SSH-клиента. Сброс отзывает
  текущие сеансы и разрешённый ключ SSH-клиента. При ошибке хранилища
  устраните её, прежде чем полагаться на сохранение сброса и отзыва после
  перезагрузки.
- **Потерян доступ к сети или сертификату.** Проверьте в локальной консоли
  вывод `network`, `ssh-key show` и сохранённые настройки. Восстановите
  доступ к доверенной сети управления и перед повторным подключением
  проверьте сертификат сервера или ключ SSH-сервера.
- **Восстановление загрузки или сброс настроек.** Создайте резервную копию
  `/home/owner` и зафиксируйте текущие записи загрузки, особенно при двойной
  загрузке. Проверьте состояние встроенным средством восстановления, прежде
  чем разрешать запись. Заводской сброс удаляет постоянные настройки и
  секреты устройства и требует проверки плана и явного подтверждения.
  При ремонте загрузки сохраните общий системный раздел EFI и записи UEFI
  других систем. Затем проверьте, что каждая сохранённая ОС загружается.
  См. [руководство по загрузке и установке](install.ru.md).
